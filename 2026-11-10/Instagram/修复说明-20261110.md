## INS-OBS-01：新增分组后列表未更新

**结论**：是确定的前端缺陷，与测试环境更新无关；已修复。

**根因**：`frontend-user/src/pages/sessions/hooks/useContactGroups.ts` 在「新建分组 / 改名 / 删除 / 加入分组」成功后，用后端返回的 `snapshot.accountId` 作为缓存键写回：

```ts
qc.setQueryData(contactGroupsQueryKey(next.accountId || id), next)
```

而 Meta / 社媒工作台的接入层回的是 **Java 渠道账号 ID**（如 `channel-…`），页面列表查询用的却是 **号 ID**（如 `9596737fcaa24428ad5fb26e5a8c507f`）。两者键不同，缓存没有换掉 → 新建成功的分组在列表和「加入分组」弹层里都不出现，直到整页刷新（重新 `list()`）才显示。这同时解释了报告里「输入清空、列表仍为空、关闭重开仍为空」和「点加入分组没有可选项」（弹层读的是同一份旧缓存）。

同目录的标签功能此前已修过同类问题（`useCustomerTags.ts:32-35` 的 `cacheCustomerTags(qc, accountId, snapshot)`，注释写明「接入层返回的 Java 账号 ID 可能不同」），分组这边漏了。

**改动**（2 个文件）：

```ts
/** 以发起查询的账号标识更新缓存；接入层返回的 Java 账号 ID 与页面用的号 ID 可能不同。 */
export function cacheContactGroups(qc: QueryClient, accountId: string | null, snapshot: ContactGroupSnapshot) {
  qc.setQueryData(contactGroupsQueryKey(accountId), snapshot)
}
```

- `apply()` 改为 `cacheContactGroups(qc, id, next)`。
- 新增单测 `src/pages/sessions/hooks/useContactGroups.test.ts`：断言按号 ID 写缓存、不会写到快照里的 Java 账号 ID 下。

**复验步骤**（IG/FB 同一个「管理分组」弹窗）：

1. 客服工作台 → Instagram → 选中号（如 `siegertwo`）→ 会话列表顶部「管理分组」。
2. 新建分组「复验-MMdd-HHmm」→ 点保存。
3. 预期：列表**立即**出现该分组（0 人），不需要刷新；关闭再打开仍能看到。
4. 选中一个会话 → 行菜单「加入分组」→ 预期弹层里能看到刚建的分组并可勾选（以前没有任何选项）。
5. 清理：删除临时分组，确认列表立即消失。

## INS-OBS-02：人工接管状态变化与局部显示不一致

**结论**：现象记录下来时测试环境正在更新（15:04 前后出现「服务暂不可用，请检查连接」「请求超时，请稍后重试」），现有证据不足以断定产品缺陷；本轮**未改代码**，只把代码层的可能性写清楚，供稳定环境复测。

**代码层事实**（IG/FB 会话页 `MetaConversation.tsx`）：

- 输入区的「AI 接待 / 人工接管」由 Java 侧接待状态反推：`human = !Java conversation.aiEnabled`（`src/api/connector-workbench.ts` 的 `connectorSettings` 返回 `human: Number(!binding.conversation.aiEnabled)`）；切换走 `POST /ai/orchestrator/takeover`（`enabled=true` 接管、`false` 交还 AI）。
- 该状态查询每 4 秒轮询一次（`MetaConversation.tsx:51`），并且 `canTakeover = !restricted && !!settings`、`takenOver = human`。若这次查询失败（Java 返回里没有 `aiEnabled` 或请求 5xx/超时），`connectorSettings` 会抛「接待状态未返回，请刷新后重试」，此时界面正好表现为报告里看到的「输入区仍 AI 接待 + 开关不可用」，直到切换会话或整页刷新让查询重建。
- 列表与标题的「人工/AI」来自另一条链路（会话列表摘要），所以会出现「列表已人工、输入区仍 AI」的局部滞后。
- 接管失败（会话已被别人接管）时后端返回「该会话已由 X 接管」，前端会以错误条提示。

**建议复测**（稳定版本上执行，记录 Java 日志时间点）：

1. A 账号：会话切人工 → 关闭并重开页面 → 期望列表、标题、输入区同时为人工，开关可用。
2. 保持人工状态下，由 B 账号发一条消息 / 发一次群发 → 期望 A 侧不自动回复、状态仍为人工。
3. 人工状态下点「交还 AI」→ 期望输入区变「AI 接待」，下一条客户消息由 AI 回复。
4. 期间抓 `lp-independent-java-1` 日志里该会话的 `state-transfer-to-human` / `release` 记录与时间，若出现自动 release，用对应 operator 追调用来源。
